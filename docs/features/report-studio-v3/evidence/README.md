# Report Studio V3 — acceptance evidence

Produced by `e2e/acceptance/report-studio-v3.spec.ts` (`npx playwright test -c acceptance.config.ts`).
Each run drove the app as a user would, against a production build (`next build` + `next start`).
The backend was isolated and used a temporary Postgres with the Olist and "E2E presentation sales" datasets.
The planner and vision model were real. Playwright traces were recorded for every scenario (`trace: 'on'`).
They are too large to commit and are regenerated by the same command.

**Commit.** S1–S7 ran at `27ea7553`. S8 was re-run at `e22fa31c` after the export fix. The only file that differs
between the two commits is `frontend/src/lib/export-pdf.ts`. `results.json` holds every assertion that ran, its
timings, and the model's own notes.

A scenario is **NOT VERIFIED** until at least one assertion has run. A skipped scenario, or one where the model
returned no design, is never recorded as a pass.

## What the runs showed (read from the images and results, not from the code)

- **S1.** The Olist report opens with its verdict: "Revenue for Jan 2018–Aug 2018 is R$ 7.4M, +137% on the same months
  of 2017 (R$ 3.1M)." Then come KPIs, trends, breakdowns, a slicer and a detail table. The sales dataset has no time
  axis, so its headline makes no time claim: "Central leads Revenue with $ 667.6K, 38% of the total."
- **S3.** The visual review ran twice, as it should. After its repairs, the re-check reported "2 of 6 repaired issue(s)
  no longer visible" and named the four that remain: KPI values slightly small, cramped pie labels, small bar labels,
  and one bar chart without data labels. These are listed as open, not claimed as fixed.
- **S4.** The three directions differ in structure, not only in colour:
  - Executive: headline + summary, light.
  - Operations: status cards + a "Needs attention" list of concentration and incomplete periods, dark.
  - Editorial: thesis, six chapters, then caveats, serif.
- **S5.** The report stays native: every tile is a live chart, and the image itself is not placed on the page. The
  model disclosed what carried over: "converted: hierarchical layout with a focus on key metrics; editorial style with
  serif typography; light mode with slate accent. approximated: spacious layout to match reference density. not
  supported here: custom header with specific text."
- **S6.** Filtering to SP changed the KPI from "R$13.6M ▲ +137% vs same months 2017" to "R$5.2M ▲ +164%". It also
  changed every narrative sentence ("R$ 7.4M, +137%" → "R$ 3.0M, +164%"). All of this was computed in about 3.9 s,
  with no stale sentence.
- **S8.** The builder, `/d` and `/embed` show the same composition. The PDF is taken from the published report and
  runs to seven readable sheets, broken between grid rows.
